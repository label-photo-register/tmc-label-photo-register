Label Photo Register · V1.4（批号 + 品名 + 规格 OCR 修正版）
===================================================

本次修正：
  1. Lot No. 保留完整连字符及后续号码，例如 50077-2606-02。
  2. Description / 品名：当整张标签 OCR 识别不全时，自动执行标签右侧文字区的第二次识别。
  3. Spec / 规格：支持识别两行或多行规格，组合进同一个 Spec 栏。
  4. 加强常见 OCR 字符错误的校正，例如 §0077-2606-02 → 50077-2606-02。
  5. 没识别的字段会提示人工检查，不以虚构数值替代。

使用方法：
  - 上传第 1 张标签照片，系统自动识别；第 2、3 张是关联物料照片。
  - 标签尽量完整填满拍摄画面，不倾斜，光线均匀。
  - 已保存记录：在左边选中旧 Label，点击「重新识别」，核对后再次「保存这一组」。
  - 重新识别只会在点击时修改当前记录字段；必须再次保存才会更新数据库。
  - 若 OCR 未准确提取，仍可手动修改。不要省略人工核对。

Excel 导出与 V1.3 一致：
  - 一张「Label Records」工作表；每个标签 1 行。
  - A、B、C 栏分别嵌入 Photo 1 / 2 / 3 小照片。
  - D 栏开始为 Label No.、Lot No.、Description、Spec 等资料。

重要：
  - 和 V1.3 沿用同一 IndexedDB 资料库 tmc_label_photo_register_1，不重置旧记录。
  - 更新网站前强烈建议先用应用内「照片 + 资料 ZIP 备份」。
  - 此部署 ZIP 不包含真实公司标签、库存数据或客户照片。
  - GitHub Pages：将 ZIP 解压后的网页文件上传到现有的 Repository 根目录，覆盖同名文件；不必建立新仓库。
  - 如 Public 仓库曾上传真实 sample-label.jpg，删除当前文件不能消除 Git 历史中的副本，请按公司资料安全要求处理。
  - 所有照片及记录仅保存在当前设备的浏览器资料库，除非使用者自行导出或上传文件。
  - 浏览器 OCR/Excel/ZIP 程序首次使用需要联网加载。

提示：Description / Spec 右侧二次识别使用这种标签的常见印刷布局。如标签位置、版式差异很大，识别仍可能失败；请检查原始照片并人工调整。

V1.5: Description 与 Spec 分行单独 OCR; 4:3 小照片框，保留原始图像长宽比; 防止 Part No. 混入规格。
